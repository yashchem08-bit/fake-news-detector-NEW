# The Wire Check — AI Fake News Detector

A 4-person team project: paste an article (or a link to one) and get
a REAL / FAKE verdict with a confidence score.

## Project structure

```
fake-news-detector/
├── data/
│   ├── raw/                    ← put Fake.csv + True.csv here (Member A)
│   └── processed/              ← generated by preprocess.py
├── data_processing/
│   ├── preprocess.py           ← Member A: cleaning + train/val/test split
│   └── scrape_url.py           ← Member A: URL → article text
├── model/
│   ├── train_baseline.py       ← Member B: TF-IDF + Logistic Regression/NB/SVM
│   ├── train_transformer.py    ← Member B: optional DistilBERT fine-tune (Phase 2)
│   ├── predict.py              ← Member B: shared inference function
│   └── saved/                  ← generated model + vectorizer files
├── backend/
│   └── main.py                 ← Member C: FastAPI app (/predict, /predict-url)
├── frontend/
│   ├── index.html              ← Member D
│   ├── style.css                ← Member D
│   └── script.js                ← Member D
├── requirements.txt
└── README.md
```

## Setup

```bash
python -m venv venv
source venv/bin/activate        # Windows: venv\Scripts\activate
pip install -r requirements.txt
```

## Run order (matches the team's phased plan)

**1. Member A — get the data ready**

Download one or more datasets with the Kaggle CLI (needs a
`kaggle.json` API token in `~/.kaggle/` — see Kaggle account settings
→ Create New Token). You don't need all three — `preprocess.py`
auto-detects and merges whichever are present:

```bash
kaggle datasets download -d clmentbisaillon/fake-and-real-news-dataset -p data/raw --unzip
kaggle datasets download -d saurabhshahane/fake-news-classification -p data/raw/welfake --unzip
kaggle datasets download -d doanquanvietnamca/liar-dataset -p data/raw/liar --unzip
```

Then check the filenames landed where the script expects (Kaggle
mirrors occasionally rename files — adjust the paths in
`preprocess.py` if yours differ):

```bash
ls data/raw data/raw/welfake data/raw/liar     # Mac
dir data\raw\ , data\raw\welfake , data\raw\liar   # Windows
```

Then run:

```bash
python data_processing/preprocess.py
```

This merges whatever sources it found, cleans the text, and writes
`data/processed/train.csv`, `val.csv`, `test.csv`.

**2. Member B — train the model**

```bash
python model/train_baseline.py
```

This trains Logistic Regression, Naive Bayes, and Linear SVM, prints
metrics for each, and saves the best one to `model/saved/`.

Optional Phase 2 upgrade (needs `transformers` + `torch`, see the
commented-out lines in `requirements.txt`):

```bash
python model/train_transformer.py
```

**3. Member C — start the backend**

```bash
uvicorn backend.main:app --reload
```

Runs at `http://localhost:8000`. Interactive API docs at
`http://localhost:8000/docs`.

**4. Member D — open the frontend**

Just open `frontend/index.html` in a browser (or serve the folder
with any static file server). It talks to the backend at
`http://localhost:8000` by default — change `API_BASE_URL` at the top
of `script.js` once you deploy the backend somewhere else.

## API reference (Member C)

| Method | Endpoint       | Body                      | Returns                                            |
|--------|----------------|----------------------------|-----------------------------------------------------|
| GET    | `/health`      | —                          | `{ "status": "ok" }`                                |
| POST   | `/predict`     | `{ "text": "..." }`       | `{ "label": "REAL"\|"FAKE", "confidence": 0-1, "elapsed_seconds": ... }` |
| POST   | `/predict-url` | `{ "url": "https://..." }`| same shape as `/predict`                            |

## Sync points

- **End of Week 1:** Member A hands off `data/processed/*.csv` to Member B.
- **Mid Week 2:** Member B hands off `model/saved/*.pkl` to Member C.
- **End of Week 2:** Member C's API is live for Member D to integrate against.
- **Week 3–4:** Full team — integration testing, polish, demo prep.

## Notes

- The frontend has no build step — it's plain HTML/CSS/JS, so anyone
  on the team can open and edit it without installing Node.
- `/predict-url` uses a simple `<p>`-tag scraper (`data_processing/scrape_url.py`).
  It won't work perfectly on every site (paywalled or JS-rendered
  pages especially) — pasting text directly is the reliable fallback.
- This tool gives a machine-learning estimate, not a fact-check —
  worth saying somewhere visible in your demo/report too.
